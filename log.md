# robot simulation lab

## base idea
A simulated robotic lab, allowing custom definitions of sensors, rendered robotic assembly and simulated operation, integration with programming IDEs, simulated camera for visual feedback,


## is a computational approach necessary
yes, real time rendering makes finding issues much simpler, manual assembly takes time which doesnt allow the rapid prototyping i want. more yabadabado


## stakeholder
Me, I want rapid prototyping of robots before actually buying anyhting because im too poor to afford components (and replacing those components).


## questionaire toward myself
> primary purpose:
> designing, testing control systems, simulating industrial robotics, researching artificial intelligence (AI), computer vision nd machine learning (ML)

> what do i expect:
> build and simulate robots, tune controllers and test algorithms on physical robot

> supported robot types:
> cartesian, 6 axis robot arms, mobile robots/vehicles, collaborative robots (cobots) and other custom designs.

> performed robot tasks:
> pick and place, path planning and navigation, manufacturing, object recognition

> simulation realism:
> real-time simulation matching physical hardware, physics based collisions, high fidelity digital twins of real equipment.

> what should a simulation model look like:
> rendered 3d visualisation, dynamics with torque and forces, contact physics, sensor simulation and a deisgnable environment for robot.

> development tool integration:
> python, c++ and rust programming should control robot. models should be importable from computer aided design (cad) software.

> interacting with simulation:
> a gui with interactive controls, data driven experiments for ai integrationa, live parameter adjustment and automated batch testing.

> physical hardware integration:
> multiple hardware platforms including mobile robots and robotic arms.

> control capabilities:
> proportional integral and derivative (PID) control, trajectory and motion planning, inverse kinematics and model based control, state space control, sensor feedback and state estimation, real time control and system identification.

> how simulation should connect to hardware:
> export generated trajectories to hardware, send commands to physical robots, recieve encoder and sesnor data, run hardware-in-the-loop experiments, compare simulated and measured performance.

> supported sensors:
> encoders and joint position sensors, force and torque, RGB cameras, IMUs

> handling data:
> plotting odometry, compare simulated and real measurements, evaluate controller accuracy

> are advanced autonomy features necessary:
> computer vision for now, in the future multi robot coordination is needed

> computing environment:
> existing personal computer (1660 super, 16gb ram, 10gb max file size)

> project organisation:
> individual projects, version control using git

> important operational features:
> documentation, reproducible experiments, easy installation and maintenance

> budget:
> under 100 pound and strictly for actual robotic parts

> software approach:
> free, open-source

> feature choosing criteria:
> industry relevant, real time performance, ease of learning, low cost
